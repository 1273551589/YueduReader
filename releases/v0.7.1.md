# YueduReader v0.7.1 — 质量收口

**一句话**：修掉 v0.7.0 里 6 个真实缺陷，小说榜首屏从 10 秒降到 2.4 秒，零编译警告。

---

## 一、榜单与搜索状态拆分（最严重的问题）

### 症状

在搜索页搜完插画（48 条）切回 Pixiv，**排行榜变成了搜索结果的 48 条**；
反过来在 Pixiv 看榜单再去搜，搜索框下面显示的是榜单内容。

### 根因

`pixivState.illusts` / `novels` / `loading` / `error` / `loadedOnce`
被两个页面**共用**。而两边的数据来源、排序语义、分页规则完全不同：

| | PixivScreen | SearchScreen |
|---|---|---|
| 数据来源 | `ranking.php` | `ajax/search/top` |
| 排序 | 榜单排名 | 搜索相关度 |
| 分页 | 按 page 翻 | 一次给全 |
| 空态含义 | 榜单没拉到 | 没搜到 |

### 修法

拆成两套字段：

```
ranking*  ← rankingIllusts / rankingNovels / rankingTags / rankingLoading / rankingError / rankingLoadedOnce
search*   ← searchIllusts / searchNovels / searchUsers / searchTags / searchLoading / searchError
```

`resetRanking()` 与 `resetSearch()` 互不干扰 —— 这一点有 4 条单测锁住
（清搜索不能动榜单，换榜不能清搜索，错误也分开）。

## 二、小说榜首屏：10 秒 → 2.4 秒

### 原来的做法（错的）

```
抓榜单 HTML → 正则提 12 个 novel id
→ 逐条打 /ajax/novel/<id>（串行，900ms 间隔）
→ 12 条全部回来才开始渲染
```

12 × 900ms ≈ **11 秒**，用户盯着转圈。

### 关键发现：榜单页里有完整 JSON

`/novel/ranking.php` 的响应里内嵌 Next.js 预加载数据，
榜单条目在 `assign.display_a.rank_a` 数组里：

```json
{"rank":1,"id":"29720928","title":"第二十二話　…",
 "user_id":"12070158","user_name":"ren.s",
 "profile_img":"https://i.pximg.net/user-profile/…",
 "character_count":"11163","word_count":"5486",
 "tag_a":["夢小説","ヒロアカ夢",…],
 "url":"https://i.pximg.net/c/100x100/novel-cover-master/…/ci29720928_…jpg",
 "series_title":"世紀末に備えすぎた…",
 "bookmark_count":971,"x_restrict":"0"}
```

**每个字段都有。** 所以一次请求就能渲染完整卡片。

### 现在的做法

```
抓榜单 HTML（1 个请求）→ 解析 rank_a → 立即上屏（实测 2387 ms）
→ 后台逐条补 /ajax/novel/<id>（作者头像、精确字数）
→ 顶部显示「正在补全详情 3/12（不影响阅读）」
```

补全失败不清空已显示内容 —— 用户能读了，不该因为第 7 条失败就整屏空白。

### 两个被真实数据打回的尝试（都记在代码注释里）

1. **正则按 `<div title=…><a href=…>` 切块**，块长上限写 8000。
   实测相邻条目间距到 **8922** → 块被截断 → 作者/字数/收藏全丢 →
   界面显示「这个榜单暂时没拿到小说」
2. **以为内嵌 JSON 是转义的**，加了 `\"` → `"` 的还原。
   实际那段就是**合法 JSON**，还原反而把它弄坏，Gson 全部解析失败

教训：**有结构化数据就别去解析 HTML**。

## 三、其余四个修复

### 3. 点 Tag 跳转（三件事必须原子）

原来点 Tag 墙的标签 → 调 `pixivSearch()` → 但本页没有渲染搜索结果的地方，
**画面完全不变**，看起来像没反应。

现在 `openPixivSearch(keyword, mode)` 一步做三件事：
切到搜索页「Pixiv插画」Tab → 写关键词 → 发起搜索。

配套把 `SearchTab` 从 Composable 局部 state 提升到 ViewModel ——
跨页面指定 Tab 必须有地方存这个意图。

### 4. 画师卡片点击

`ArtistCard(user, onClick = { })` —— 空实现。

现在点卡片进画师详情页：头像 + 昵称 + ID + 作品数 + 双列作品网格，
点作品进大图浏览器。

**数据来源实测**：

| 接口 | 免登录 | 结果 |
|---|---|---|
| `/ajax/user/<uid>/illusts` | ❌ | 403「不正确的请求」 |
| `/ajax/user/<uid>/profile/all` | ✅ | 326 个作品 ID |
| `/ajax/illust/<id>` | ✅ | 单条详情 |

所以是「先拿 ID 列表（1 个请求）→ 逐条取详情」，`limit` 默认 24。

顺带发现 **Compose 命中测试的坑**：卡片内层的头像/昵称会截获点击，
点中间没反应。给内层 `Column` 补了 `clickable { onClick() }` 才通。

### 5. Coil 走动态代理

v0.7.0 的 `PixivApplication.newImageLoader()` **完全不读** `Settings.proxyUrl`。
结果：配了代理后 Pixiv 页文字能刷、**图片全是灰块**。

修法用 `ProxySelector` 而不是 `.proxy(...)`：

```
.proxy(...)      → 建 Client 时固定，改设置必须重启
ProxySelector    → 每次请求现读设置，改代理立即生效
```

`DynamicProxySelector` 带 500ms 缓存（列表快速滚动时不反复读 SharedPreferences），
解析规则与 `PixivClient` 共用同一个 `parse()` —— 代理串的真相点只有一处。

支持：`host:port` / `http://host:port` / `socks5://host:port`，
解析失败一律退直连（写错的代理串不该让整个 App 断网）。

### 6. 零警告

清掉 20 处编译警告：

- `Icons.Filled.ArrowBack` 等 → `Icons.AutoMirrored.Filled.*`（7 个文件）
- `ResponseBody?` 非空后的多余 `?.`（4 处）
- elvis 左侧永远非空（3 处）
- 不必要的 `!!`（2 处）
- `Context()` 弃用 —— Rhino 1.7.15 只有这一个入口，用
  `@Suppress("DEPRECATION")` + 注释说明为什么不能改

## 六、已知限制

1. **画师作品是 N+1** —— `profile/all` 只给 ID，逐条取详情。
   30 件作品 ≈ 31 个请求（串行），约 25 秒。分页加载留到下一版。
2. **小说榜仍只取 12 条** —— 首屏控制请求数，翻页未做。
3. **R18 榜单需要登录** —— 未登录时明确提示，不给空列表。
4. **图床镜像可用性不定** —— `i.pixiv.re` 当前对任意 path 返回 404。
