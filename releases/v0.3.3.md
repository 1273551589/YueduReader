## 修复：搜索阶段的 `@js` 完全失效

```kotlin
val per = AnalyzeRule().apply { ... }           // 每条结果 new 一个，但没挂 JS
val name = per.getString(rule.name ?: "@text")  // @js 规则 → UnsupportedApi
if (name.isEmpty()) continue                    // → 整条结果被跳过
```

**任何用 `@js` 写 `ruleSearch.name` 的书源，搜索结果一条都出不来。** 实测：2 条结果 → `hits=0`。

目录阶段反而是对的，因为那里单独写了 `attachJsForElement`。这是「四个阶段写了四遍、漏了一处」的结构性问题。

修复后 `hits=2`。加了 4 条测试，注入回归验证能抓住：

```
FAILED  搜索阶段条目级 @js 能取到值  expected:<2> but was:<0>
```

## 修复：连续失败计数只存了一条

```kotlin
File(dir, "failures.json").writeText(gson.toJson(mapOf(result.sourceUrl to failures)))
```

多源时**前面的全被覆盖**。「连续 3 次失败建议删除」从 v0.1.0 就写进 README 了，实际上一直不工作。

## 差点误报的一处

一开始以为 `attachJs()` 里 `currentContent = { null }` 是缺陷，加了参数传内容进去。**注入回归验证后发现它不改变任何行为** —— 因为 `AnalyzeRule` 已经把 HTML 存自己身上了，那个 `content` 只是兜底路径。已把多余参数删掉。
