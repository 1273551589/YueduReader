## 一、Pixiv 端口：免登录就能用

### 实测出来的接口真相

开工前先把接口全探了一遍。**v0.6.0 计划里写的 `ajax/top/*` 是要登录的**，
照那个写等于一上线就全空：

| 能力 | 接口 | 免登录 | 实测 |
|---|---|---|---|
| 插画 / 漫画榜 | `ranking.php?mode=X&content=Y&format=json` | ✅ | 50 条完整数据 |
| 小说榜 ID | `novel/ranking.php`（HTML 里抽 id） | ✅ | 每页 103 个 id |
| 作品详情 | `/ajax/illust/<id>`、`/ajax/novel/<id>` | ✅ | 含正文 |
| 搜索 / 相关 tag | `/ajax/search/top/<kw>` | ✅ | 插画 48 + 小说 8 + tag |
| `ajax/top` 系列 | — | ❌ | 403「不正确的请求」 |
| R18 榜单 | — | ❌ | 需 PHPSESSID |

所以主通道用前四个，`ajax/top` 一次都不用。

### 三条硬约束（都是踩出来的）

**1. 必须串行。** 对 `pixiv.net` 打 4 并发，立刻
`SSL: UNEXPECTED_EOF_WHILE_READING` —— Pixiv 在 TLS 握手层就掐断。
所有请求走同一把 `Mutex` + 900ms 间隔。

**2. 必须带 Referer。** 图床 `i.pximg.net` 不带
`Referer: https://www.pixiv.net/` 直接 **403**（带则 200）。
拦截器挂在 Coil 的全局 `ImageLoader` 上 —— 书封、头像、大图、
Tag 墙全走同一条路，漏一处就裂一张图。

**3. 必须重试。** 即使串行，仍有约 20% 条目偶发返回空 body。
重试 2 次后基本都能拿到。

### 小说榜为什么是 N+1

小说榜**没有** `format=json`（实测返回 `{"error":true}`），只能抓 HTML。
但不解析 DOM class（那是 CSS-in-JS 哈希，Pixiv 每次发版都变），
而是**正则抓 `/novel/show.php?id=\d+`** —— 作品链接格式是稳定契约。

拿到 ID 后逐条走 `/ajax/novel/<id>` 取完整元数据。
代价是 N 次请求，换来的是字数/收藏/tag 全齐、且不怕 Pixiv 改版。

### Pixiv 小说正文语法

| 标记 | 处理 | 为什么 |
|---|---|---|
| `[newpage]` | → 空行 | 直接删会把两段粘成一段 |
| `[chapter:标题]` | 拆章 | 决定目录结构 |
| `[[rb:汉字>假名]]` | → `汉字（假名）` | 只留汉字丢读音，只留假名读了不懂 |
| `[jump:N]` | 删除 | 留在正文里就是噪音 |
| `[pixivimage:123]` | → `［插图 123］` | 比一串 ID 可读 |

正文一次拉回全文、本地切章，所以切章是**纯内存**操作，零网络。

## 二、修掉的三个真 bug

### bug 1：「保存原图」实际存的是缩略图

**症状**：点保存得到 `449×960 / 682 KB`，而真原图是 `2805×6000 / 7.18 MB`。

**根因**：我把 `c/480x960/img-master/.../152421696_p0_master1200.jpg`
改成 `img-original/.../152421696_p0_master1200.jpg` —— 404。
`_master1200` 是 `img-master` 目录下的**转码标记**，原图文件名里没有它。

**修法**：`img-original/.../152421696_p0.jpg`（去掉 `_master1200`）。
实测这条路径返回 200 / 7,188,686 字节，与本地 curl 完全一致。

顺带加了两道校验：状态码 2xx **且** 大小 > 1KB **且** 文件头是 PNG/JPEG。
（Pixiv 的 404 体是 58 字节 JSON，光看状态码会把它存成 `.jpg`。）

### bug 2：Tag 墙 16 个格子全是灰块

**症状**：标签名正常，封面全空。

**第一版错误**：封面从 `ps.illusts` 里按「作品的 tag 包含这个词」去匹配，
但首次进入页面时 `illusts` 是空的 → 匹配不到 → 全空。

**第二版也没修对**：改了 ViewModel 加了 `tagCovers`，
但 UI 那边读的还是旧字段 —— 因为字符串替换断言失败没发现。

**最终**：每个 tag 各搜一次，首图存进 `tagCovers`（tag → url），
UI 直接读它。联网诊断测试确认 `covers=8 / tags=8`。

### bug 3：`LazyVerticalGrid` 里 `aspectRatio(1f)` 算出 0 高度

格子可见但图是空白。改成固定 `height(160.dp)`。

### 顺手修的 v0.6.0 遗留

- **搜索页死锁**：`if (mode == IMAGE) { ...; return }` 把模式胶囊放进了分支内，
  切到「搜图片」再也切不回来。现在标题栏 + 胶囊永远在最外层。
- **搜索串行**：`for (src in enabled)` 20 个源要等 30 秒。
  改成按域名分组并发（同域串行 + 800ms，跨域最多 4 并发），
  实测 2 源 1.5 秒返回 29 条。同时跳过体检硬失败的源。
- **R18 硬过滤**：搜索结果聚合**之前**过 `BookClassifier`，
  关开关时成人向条目进不了列表。
- **阅读器**：真左右翻页（`TextMeasurer` 精确分页）、
  点击左/中/右分区、底部快捷面板（字号/行距/纸色/翻页）、
  正文插图 `AsyncImage` 渲染、章内页码精准恢复。
- **书城**：跨源去重补全缺失封面/简介/字数、`altOrigins` 打通换源、
  30 分钟快照缓存（冷启动秒出）。

## 六、已知限制

1. **R18 榜单需要登录** —— 未登录时明确提示去设置填 Cookie，不给空列表
2. **画师搜索是反查** —— Pixiv 无免登录用户搜索接口，按作品反查作者
3. **小说榜首屏较慢** —— N+1 请求 + 串行，12 条约 10 秒
4. **图片镜像可用性不定** —— `i.pixiv.re` 当前对任意 path 返回 404，
   保留为可选项；官方直连 + Referer 是可用路径
5. 搜索仍是 4 并发上限，未做可配置
