## 三个大缺口补上了

对应 v0.1.0 README 里列的三条「下一步建议」。

## ① `@js` 支持 —— 已打通

嵌入 Rhino **1.7.15**（不是 1.9.x：1.9 编译到 Java 11+ 字节码且走 `java.lang.invoke` 路径，Android 上不一定有；1.7.15 是 Java 8 字节码，稳）。

**只绑定 62 条样本源里真实用到的 8 个 API**：

| API | 62 条中出现 |
|---|---:|
| `java.base64` | 25 |
| `java.ajax` | 14 |
| `java.get` | 14 |
| `java.log` | 10 |
| `java.getString` | 6 |
| `java.encodeURI` | 6 |
| `java.put` | 4 |
| `java.getElements` | 3 |

`Packages.*` 仍禁用（安全策略，只损失 1/62 源）。

## ② 分页 —— 效果比预期大

同一章正文从 **409 字变成 24374 字**，真机第一章 **53165 字**。这是「能不能读完一本书」的分水岭。

`nextTocUrl` 对 SF 无用（核实过：单页 29 个 `catalog-list` 块、421 个 `<li>`，没有分页），但别的站点需要，所以还是实现了（50 页上限 + 防环 + 404 时保留已抓内容）。

## ③ 正则超时 —— 但教科书例子不成立

实测 JDK 17：

| pattern | 耗时 |
|---|---:|
| `(a+)+$` | **1 ms** |
| `(a\|aa)+$` | 0 ms |
| `(.*a){30}` | **14 455 ms** |

JDK 9+ 对「单字符重复的嵌套量词」做了度量化优化，教科书那批 ReDoS 例子**已经打不动了**。按 `(a+)+$` 估会误以为正则超时很罕见。

## 已知问题（v0.3.0 修复）

**JS 超时是假的**：只调了 `setInstructionObserverThreshold(10_000)` 但没重写 `observeInstructionCount`，等于设了闹钟没接电话。`while(true){}` 会让 2 线程的 `js-rule` 池永久耗尽。
