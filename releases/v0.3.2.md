## 修复：`Context.enter()` 复用实例导致预算串台

### 机制（实测 Rhino 1.7.15）

```
enter() → exit() → enter()        → makeContext 被调用，新实例
enter() → enter()（不 exit）       → makeContext 不调用，同一个实例
```

**只要 `exitClean()` 正常走到 `Context.exit()`，预算本来就不会串。** 所以所有端到端计时测试都在验证正常路径，等于没测到。风险只在**嵌套 `enter`** 或**异常路径没 exit** 时。

实测（1 线程池，先 20s 预算、再 800ms 预算）：

```
task2 拿到的 ctx 预算字段 = 30000   ← 应是 800
❌ 3s 未结束 —— 预算完全没生效
```

修复：`budget` / `startedAt` 改成可刷新的 `var`，`enterWithBudget()` 里每次显式 `resetBudget()`。

### 能确定性抓住它的测试

不靠计时，直接构造嵌套：

```kotlin
val a = enterWithBudget(30_000)
val b = enterWithBudget(800)        // 不 exit 就再 enter
assertEquals(800L, b.debugBudget)    // 不刷新这里就是 30000
```

**回归注入验证**（注掉 `resetBudget`）—— 全量 51 个测试里**只有这一条失败**：

```
FAILED  不应有错误：[第2层预算=30000，应为 800, 第3层预算=30000，应为 900]
```

其余 50 条全是正常路径，抓不住。
