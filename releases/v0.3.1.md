## 修复：两个 JS 超时缺陷（其中一个由 0.3.0 引入）

### 缺陷二（0.3.0 引入，更隐蔽）

预算放在 `ContextFactory` 的全局变量上，`makeContext()` 不知道是哪个实例在跑：

```
JsRuntime(timeoutMs = 600) 实际会按全局 30 秒跑
→ 外层 future.get(600ms) 只是让调用方提前返回
→ 内层还在烧 CPU 三十秒
```

**这比原来的 bug 更麻烦，因为它看起来「修好了」。**

改成预算走 `ThreadLocal`，按执行传递；`JsRuntime` 持有 context 引用供外层超时直接打断。

### 缺陷三：`cancelCurrent()` 是死代码

`Context.getCurrentContext()` 是 thread-local，从调用方线程调用它，拿不到跑脚本的那个 Context。

### 新增 5 条测试

都带 `timeout`，失败会挂起而不是静默通过：能打断、预算跟实例跑、并发互不干扰、线程真的 `TERMINATED`、打断后同一实例仍可用。

### 顺带：体检耗时 9.6s → 2.9s

`@js` 曾对每个目录条目无条件建 `JsRuntime`，SF 421 章就白建了 421 个 Rhino 引擎。加了 `needsJs()` 前置判断。

## ⚠️ 本版遗留问题（0.3.2 修复）

`Context.enter()` 在**同一线程**上会复用上次的 Context 实例，`makeContext()` 不会被再调用 —— 线程池复用线程时预算仍是旧的。
