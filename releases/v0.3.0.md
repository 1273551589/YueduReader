## 修复：JS 超时从来没生效过

v0.2.0 的 `js-rule` 线程池只有 2 个线程，而一个 `while(true){}` 就能永久占死一个。

```kotlin
ctx.setInstructionObserverThreshold(10_000)   // 设了闹钟
// ← 但整个文件没有任何 override observeInstructionCount，等于没接电话
```

实测（Rhino 1.7.15 / JDK 17）：

```
while(true){} 跑在独立线程 → 2 秒后 interrupt()
→ 线程状态仍是 RUNNABLE，脚本继续跑，永远不停
```

`future.cancel(true)` 只是把 Future 标记成已取消，脚本还在跑。

修复：继承 `Context` 并**重写 `observeInstructionCount`**，超出预算抛 `EvaluatorException`。实测：

```
✅ 死循环被中断: EvaluatorException / script timeout
3 秒后线程状态: TERMINATED
```

新增 3 条测试锁死（`JsInterruptTest`），含「打断后同实例仍可继续用」。

## 关于 ReDoS 测试用例的选择

教科书那批例子在 JDK 9+ 已被度量化优化，按它们写测试会**误通过**。能用的是 `(.*a){30}`（实测 14.5 秒）。

## ⚠️ 本版遗留问题（0.3.1 修复）

把预算改到 `ContextFactory` 的全局变量上，但 `makeContext()` 不知道这次是哪个 `JsRuntime` 在跑 —— **实例的 `timeoutMs` 形同虚设**。
